# player 预期

> 本文只写「应该是什么样」，不写技术选型、不写模块划分。
> 实现细节等 manager 与 simple 落地后再单独规划。

---

## 1. 定位

一个独立的桌面音乐播放器。它不管理音乐，只播放 manager 已经配置好的歌单。

打开就能用：左边选歌单，中间看当前这首，右边看接下来是什么。

---

## 2. 使用场景

| 场景 | 期望 |
|---|---|
| 想听某个歌单 | 打开 player → 点歌单 → 自动开始播 |
| 听到一半去干别的 | 关掉窗口，下次打开还在原处，按播放继续 |
| 突然不想听这首 | 点下一首，或按窗口内快捷键 |
| 想跳过一整批不喜欢的 | 由自适应决定，用户不需要干预 |
| 想调小一点 | 拖音量条，或按 ↑ / ↓ |

---

## 3. 界面预期

```
┌──────────────┬───────────────────────────────┬──────────────┐
│ 歌单          │ 正在播放                       │ 待播队列      │
│              │                               │              │
│ 默认歌单   37 │   Experience                  │ 1  Yellow…   │
│ 深夜       12 │   Ludovico Einaudi            │ 2  Aware     │
│ 通勤       28 │                               │ 3  Eternity  │
│              │   00:42 ──────●──────── 05:44 │ 4  Rapture   │
│              │                               │              │
│              │   ⏮   ▶   ⏭      🔀  🔁  🔂     │              │
│              │                               │              │
│              │   🔊 ───────●───  80%          │              │
└──────────────┴───────────────────────────────┴──────────────┘
```

- **左栏**：歌单列表，显示名称与歌曲数，当前歌单高亮。底部显示当前播放模式。
- **中栏**：当前曲名（大）、作者、进度条、时间、上一首/播放/下一首、模式按钮、音量。
- **右栏**：待播队列，可以收起。点任意一首直接跳过去。
- 没有封面，没有歌词，没有可视化频谱。中间区域就是文字 + 控件，留白要够。
- 深浅两套配色，跟随系统或手动切换。

**空状态**：没有歌单时，中间显示一句「还没有歌单，先去管理器建一个」+ 一个「打开管理器」的按钮。

## 4. 行为预期

### 4.1 播放

| 操作 | 行为 |
|---|---|
| 点歌单 | 载入该歌单，从第一首开始播放 |
| 点队列里的歌 | 立刻切到那首，当前进度丢弃 |
| 播放/暂停 | 保留进度；再按继续 |
| 上一首 | 回到上一首。**没有「3 秒内重播本曲」这种规则**；停在第一首时按钮不可用 |
| 下一首 | 切下一首，并记为一次「跳过」（是否算跳过由实际播放时长决定） |
| 拖进度条 | 松手即跳转，不卡顿 |
| 拖音量 | 即时生效，记忆到下次 |
| 播完一首 | 自动下一首；列表到底按模式处理，三种模式都不会停 |

### 4.2 播放模式

**没有「顺序播放」这种模式。** 只有三个，而且三个都是无尽的：

| 模式 | 行为 |
|---|---|
| 随机 | 每轮洗牌，一轮内不重复；新一轮首曲不与上一轮末曲相同 |
| 列表循环 | 按顺序播，播完最后一首回到第一首 |
| 单曲循环 | 重复当前曲；用户点下一首或按快捷键才换 |

模式切换即时生效，不需要重新载入歌单。

**单曲循环可以脱离歌单选歌**：中间区域的曲名旁有一个「选一首循环」入口，可以从**全部曲目**里挑任意一首，不必先切歌单。选中的歌不在当前歌单里时，队列区显示「单曲循环：<歌名>」，退出单曲循环后回到原歌单的当前位置。

### 4.3 队列

- 队列展示「接下来会播什么」，顺序与当前模式一致。
- 队列里可以双击跳转。
- 自适应跳过的歌**不留在队列里**——判定发生时就地移除，队列始终反映真实走向。
- 队列可收起，收起后中间区域自动变宽。

### 4.4 自适应

歌单开了自适应时，切歌前先判定：

- 判定为跳过 → 直接切下一首，界面不弹提示、不闪警告。用户只会发现这首没播。
- 队列同步更新。
- 判定依据与记录规则由歌单配置决定，player 不提供修改入口，也不显示概率。

理由：这是「后台帮你过滤」，不是「需要你确认的建议」。任何提示都会打断听歌。

### 4.5 记忆

- 记住上次的歌单、当前曲目、播放位置。
- 重新打开时处于**暂停**状态，停在原位，点播放才继续。
- 音量、模式、窗口大小、队列展开状态一并记住。

### 4.6 窗口内快捷键

**不做硬件媒体键，不做全局热键。** 只响应 player 窗口在前台时的按键：

| 按键 | 行为 |
|---|---|
| `Space` | 播放/暂停 |
| `←` / `→` | 快退 / 快进 5 秒 |
| `Ctrl+←` / `Ctrl+→` | 上一首 / 下一首 |
| `↑` / `↓` | 音量 ±5% |
| `Esc` | 收起队列面板 |

理由：硬件媒体键与全局热键会跟系统或别的播放器抢键，而这个播放器的使用场景是「坐在电脑前听歌」，窗口内按键已经够用。

## 5. 与其他两个程序的关系

| 关系 | 说明 |
|---|---|
| 与 manager | 只读它配置的歌单与设置；不回写音乐库 |
| 与 simple | 互不干扰，可以同时开；两边都按各自规则播放并记录 |
| 数据一致性 | player 只写「播放位置」与「自适应记录」，不碰音乐库 |

player 不是 manager 的子窗口：关掉 manager 后 player 照常工作。

---

## 6. 不做什么

- 不做封面、不做歌词、不做频谱可视化。
- 不做硬件媒体键、不做全局热键。
- 不做音乐库编辑：改名、改标签、导入、删除都在 manager 里。
- 不做在线流媒体、不做网络电台。
- 不做均衡器、不做音效、不做变速变调。
- 不做多窗口、不做迷你悬浮窗。
- 不做播放历史列表。

---

## 7. 异常预期

| 情况 | 期望 |
|---|---|
| 歌单为空 | 中间区域给空状态，不自动播放 |
| 某首歌的文件丢失 | 跳过它，在队列里标灰并给一句「文件缺失」，继续下一首 |
| 上次记住的歌单已被删除 | 回到「选个歌单开始」的空状态，不报错 |
| 上次记住的歌已不在歌单里 | 停在该歌单第一首、暂停状态 |
| 播放失败 | 顶部一行浅色提示，不弹窗、不中断整个队列 |

---

## 8. 已确认

| 事项 | 决定 |
|---|---|
| 队列 | 只支持跳转，不支持拖拽调序、不支持删除单曲 |
| 最近播放 | 不做 |
| 窗口尺寸 | 默认 960×620，最小 760×480 |
| 单曲循环时的队列 | 仍显示整张歌单，当前曲高亮 |
| 单曲循环选歌 | 可以从全部曲目里直接挑一首，不限于当前歌单 |
| 关窗口 | 退出程序 |
