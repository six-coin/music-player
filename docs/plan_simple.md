# simple 实施计划

> 本项目遵循 `reference.md`。偏离标准的地方集中记录在 §10。
> simple 是一个命令行播放器：双击就开始播默认歌单，没有菜单、没有选择界面。

---

## 1. 目标与边界

### 1.1 一句话

读取 manager 维护的默认歌单，按配置的播放模式（随机 / 列表循环）连续播放，用单键控制跳过与退出，并把每次播放结果记进该歌单的自适应记录。

### 1.2 做什么

| 能力 | 说明 |
|---|---|
| 直接播放 | 启动即播默认歌单，不询问、不选歌单 |
| 播放模式 | 只有两种：随机、列表循环；取自 manager 的 simple 设置页 |
| 跳过 | `Ctrl+C` 跳过当前曲 |
| 退出 | `Ctrl+Q` 退出程序 |
| 自适应 | 按歌单规则判定是否跳过，并按实际播放时长记录结果 |
| 状态显示 | 当前曲名、作者、歌单名、第几首 / 共几首、当前模式、键位提示 |

### 1.3 不做什么

- 不做选择菜单、不做歌单切换、不做搜索。
- **不做任何配置界面**：所有配置都在 manager 里改，simple 只读取。
- 不做暂停/继续、不做音量、不做进度条、不做拖动。
- 不做定时关机。
- 不做播放历史列表、不做收藏。
- 不写音乐库，只写统计。

一句话：**功能严格少于旧版**，只多「自适应」这一项。

simple 自己独有的配置只有一个「播放模式」，两项可选；其余参数（自适应四项、主题等）都由三端共用，放在 manager 的通用页。

## 2. 运行形态

### 2.1 入口

| 文件 | 说明 |
|---|---|
| `simple.py` | 入口薄壳，延迟导入 `app.cli.simple`，调 `main()`；不超过 30 行 |
| `simple.bat` | 用 `.venv\Scripts\python.exe` 启动（**不是** `pythonw`，命令行程序需要控制台） |

`simple.bat` 与另外两个 bat 同一套模板：`@echo off` / `chcp 65001` / `setlocal` / `cd /d "%~dp0"` / 检查解释器存在 / 出错 `pause` + `exit /b 1`。

### 2.2 依赖

只有 `python-vlc` 与 `loguru`。VLC 本体需要用户机器上装有 VLC（`python-vlc` 只是绑定）。

启动时先探测 VLC 是否可用：不可用就打印一句人话（含下载地址）并以退出码 1 结束，不要抛一长串 traceback。

## 3. 行为

### 3.1 启动序列

```
初始化日志
  → 读 settings.json（失败则用默认值并警告）
  → 读 playlists.json，取 default_uid
  → 解析默认歌单 → 去重集合
  → 集合为空？→ 提示「默认歌单里还没有歌曲，请先在管理器中导入」→ 等一次按键 → 退出码 1
  → 进入播放循环
```

读的配置项只有三处：`simple.order`、`common.adaptation`、默认歌单自身的 `adaptation` 覆盖。不读 `library.json` 的全部内容也可以：显示只需要歌名与作者，按需查表即可。

### 3.2 播放循环

```
songs = 默认歌单解析结果（集合）
order = settings.simple.order

loop:
    queue = 按 order 生成一轮队列
    for md5 in queue:
        if 自适应判定为跳过:
            记日志，continue
        播放 md5
        outcome = 等待「播完 / 用户跳过 / 用户退出」
        按 outcome 记录统计
        if 用户退出: 清理并 return
```

只有两种模式，且都是无尽的：

| 模式 | 行为 |
|---|---|
| `shuffle` | 每轮开始前洗牌；一轮内每首恰好一次；新一轮的第一首不与上一轮最后一首相同 |
| `list_loop` | 手动歌单按用户设定的顺序播；条件歌单按歌名排序播。播完最后一首回到第一首 |

关于「一轮内会不会重复」：不会。一轮就是一次洗牌，集合里每首只出现一次。唯一可能撞的是**轮与轮的接缝**——上一轮的最后一首恰好又是新一轮的第一首，听感上像「连着放了两遍」。所以只处理接缝：新一轮洗好后若首尾相同，把第一首与中间某首交换。

`shuffle` 的队列在**每轮开始时**生成一次，不预先展开整张歌单——歌单可能有几百首，预生成没有意义。

### 3.3 自适应

判定与记录全部走 `app/core/adaptation.py`，与 player 共用同一份实现，simple 不自己算。

**判定**（播放前）：

```
n = 已有记录条数
s = 其中跳过的条数
n <= min_plays → 不跳过
否则 p = min(base, 0.99) × s / n，random() < p 则跳过
```

**记录**（播放后）：

| 情形 | 记录 |
|---|---|
| 阈值内按 `Ctrl+C` | `1` |
| 播过阈值后按 `Ctrl+C` | `0` |
| 自然播完 | `0` |
| 短于阈值的歌自然播完 | `0` |
| 自适应自动跳过 | 不记录，只累加 `auto_skipped` |
| `Ctrl+Q` 退出 | 不记录 |

计时用 `time.monotonic()` 差值，只在真正出声的时段累加。simple 没有暂停，所以「实际播放时长」就等于「从 `play()` 到切歌」的墙钟时间；但仍然走同一个计时接口，方便以后加暂停。

参数（`window` / `min_plays` / `base` / `skip_seconds`）全部来自歌单配置，歌单没覆盖就用 `common.adaptation` 里的全局默认值——那四项在 manager 的**通用**页，与 player 共用同一份。simple 界面上不提供任何修改入口。

### 3.4 键位与输入层

这是本次唯一需要「重新设计」的地方。

**为什么不用 `try/except KeyboardInterrupt`**：它把「跳过」这件事绑死在异常流上——加不了第二个动作、改不了键、测不了、还会在阻塞调用里延迟触发。要的是「按键 → 动作」的映射表，而不是异常。

**做法**：一个可复用的控制台输入层 `app/cli/console.py`。

```
ConsoleSession（上下文管理器）
  ├─ 进入：GetConsoleMode 保存原模式
  │        清掉 ENABLE_LINE_INPUT | ENABLE_ECHO_INPUT | ENABLE_PROCESSED_INPUT
  │        开启 ENABLE_VIRTUAL_TERMINAL_PROCESSING（为了 ANSI 清屏与颜色）
  └─ 退出：原样恢复（异常、Ctrl+Q、窗口关闭都要走到）

read_key(timeout_ms) -> bytes | None
  └─ msvcrt.kbhit() + getch()，超时返回 None，不阻塞主循环
```

关掉 `ENABLE_PROCESSED_INPUT` 之后，`Ctrl+C` 不再触发 SIGINT，而是作为一个普通字节 `0x03` 被 `getch()` 读到。于是它和别的键走同一条路径。

**绑定表是数据，不是代码**：

```python
BINDINGS = {
    b"\x03": Action.SKIP,  # Ctrl+C
    b"\x11": Action.QUIT,  # Ctrl+Q
}
```

以后想加 `Ctrl+P` 暂停，只需在表里加一行、在动作枚举里加一项，不动主循环。

**控制台事件**：注册 `SetConsoleCtrlHandler` 处理 `CTRL_CLOSE_EVENT` / `CTRL_LOGOFF_EVENT` / `CTRL_SHUTDOWN_EVENT`——用户直接点窗口右上角关闭时，要停掉 VLC、恢复控制台模式、刷日志，而不是留一个还在出声的孤儿进程。

### 3.5 显示

固定一块区域，只在状态变化时重绘（换歌、跳过、模式变化），不做逐帧刷新——逐帧刷新会闪，也会吃 CPU。

```
┌────────────────────────────────────────────────┐
│  正在播放                                       │
│                                                │
│  Experience                                    │
│  Ludovico Einaudi                              │
│                                                │
│  歌单  默认歌单                    第 3 / 37 首  │
│  模式  随机                                     │
│                                                │
│  Ctrl+C 跳过        Ctrl+Q 退出                 │
└────────────────────────────────────────────────┘
```

- 颜色只用青（标题/边框）、蓝（字段名）、白（值）、灰（提示），克制、不刺眼。
- 自适应跳过是**静默**的：不打印「已自动跳过」，界面直接换成下一首。日志里记一条，供排查。
- 不显示播放进度、不显示剩余时间——那属于新增功能。

## 4. 与其他程序共享的数据

| 文件 | simple 的权限 |
|---|---|
| `config/settings.json` | 只读 `simple.order` 与 `common.adaptation` |
| `config/playlists.json` | 只读 `default_uid` 与该歌单的 `filters` / `adaptation` |
| `config/library.json` | 只读，用于显示歌名与作者 |
| `config/stats/<playlist>.json` | 读写 |

写入统计时按「读 → 改 → 原子替换」执行，并持有该歌单的锁文件。player 同时开着也不会互相覆盖。

## 5. 代码结构

```
app/cli/
├─ __init__.py
├─ simple.py       启动、播放循环、状态机
├─ console.py      控制台模式、单键读取、绑定表
└─ render.py       固定区域绘制与 ANSI 转义
```

`simple.py` 只做编排：解析歌单、生成队列、调用播放器、记录结果。判定与记录在 `core`，输入在 `console`，绘制在 `render`。播放器本身抽成一个薄接口（`play(md5)` / `is_playing()` / `stop()`），测试时注入假实现，不启动真实 VLC。

## 6. 错误处理

| 场景 | 策略 |
|---|---|
| VLC 不可用 | 启动时检测，打印安装指引，退出码 1 |
| 默认歌单为空 / 不存在 | 打印「请先在管理器中配置默认歌单」，等一次按键，退出码 1 |
| `settings.json` 损坏 | 用默认值继续，屏幕顶部一行黄色警告，日志记 error |
| 单曲文件缺失 | 跳过该曲，记 warning，继续下一首 |
| 单曲播放失败 | 同上，且不计入自适应记录（不是用户的选择） |
| 统计写入失败 | 记 error，不影响播放；下次播放继续尝试 |
| 用户直接关窗口 | 控制台事件处理器停播、恢复模式、刷日志 |
| 未捕获异常 | 记录堆栈，打印一行摘要，退出码 1（命令行程序不留黑框，但也不静默） |

退出码约定：`0` 正常退出，`1` 启动失败，`2` 运行中致命错误。

## 10. 偏离标准

| 条目 | 偏离 | 原因 |
|---|---|---|
| 1.6 目录 | 没有独立的 `ui/`，改由 `cli/` 承担界面职责 | 命令行界面没有 DOM，分层按「输入 / 渲染 / 编排」切更合适 |
| 3.x 界面 | 不使用 pywebview | 启动速度是这类工具的核心体验，命令行最合适 |
| 2.10 本地化 | 屏幕文案直接写中文，不走 i18n | 命令行输出是给本机用户看的，切换语言无意义 |

## 11. 已确认的决定

| 事项 | 决定 |
|---|---|
| 播放模式 | 只有随机、列表循环两种，都是无尽的 |
| 配置入口 | simple 不提供任何配置界面，全部在 manager 里改 |
| 专属配置 | 只有 `simple.order` 一项，在 manager 的 simple 页 |
| 共用配置 | 自适应四项与「前 30 秒」阈值放 manager 的**通用**页 |
| 单曲循环 | 不做 |
| 定时关机 | 去掉 |
| 跳过键 | `Ctrl+C`，用控制台输入层实现，不用 `try/except` |
| 退出键 | `Ctrl+Q` |
| 已播时长 | 不显示 |
| 自动跳过提示 | 不提示，只记日志 |
| 默认歌单为空 | 打印提示，等一次按键再退出 |

## 12. 补充确认

| 事项 | 决定 |
|---|---|
| 列表循环顺序 | 手动歌单按用户设定顺序；条件歌单按歌名 |
| 一轮只有一首歌 | 随机模式退化为单曲重复，不做特殊处理 |
| 单实例 | 第二次启动打印「simple 已经在运行」并以退出码 0 结束 |

simple 的单实例用命名互斥量实现，与 manager 同一套工具函数；manager 的「打开 simple」先探测互斥量，已在运行就不再拉起。

## 13. 实现备注

S1–S4 落地时定下的细节，补上面没写死的地方。

| 事项 | 实现 |
|---|---|
| VLC 适配器位置 | `app/system/vlc.py`（`probe()` + `VlcPlayer`）。§5 只列了 `app/cli`，但按分层规则 `system` 才是外部库的位置，`cli` 只管输入、绘制与编排 |
| 自适应开关 | 取默认歌单自己的 `adaptation.enabled`，界面上有一行「自适应 开/关」。**关掉时既不判定也不写统计**——记录只服务于自适应，关掉就不该再动文件 |
| 参数来源 | `common.adaptation` 统一由 `core/adaptation.py::params_from_dict()` 读取（夹取 + 类型兜底），manager 设置页与 simple 共用这一份 |
| 播完判定 | 轮询 `is_playing()`：先等它变 True（5 秒不出声按播放失败处理），再等它连续 0.4 秒为 False 才算播完 |
| 接缝判断 | 用「上一轮**实际出声**的最后一首」，被跳过或播不出来的不算，听感才对 |
| 等一次按键 | 标准输入不是控制台时直接返回，免得被重定向或计划任务拉起时挂住 |
| 关窗口 | 关掉 `ENABLE_PROCESSED_INPUT` 之后 Alt+F4 不再由窗口处理，而是作为按键送进来。实测控制台给的是 `0x00 0x6B`（裸 F4 是 `0x00 0x3E`），两个都绑到退出，写死不可配 |
| 显示宽度 | 东亚宽度模糊（`A`）字符按两列算：中文控制台把 `…`、`·` 渲染成两格，按一格算会让整行短一格、右边竖线错位 |
| 测试 | 计划里的四个文件之外，另加 `tests/test_simple_render.py` 测方框对齐与转义序列 |
