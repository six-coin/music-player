# manager 实施计划

> 本项目遵循 `reference.md`。偏离标准的地方集中记录在 §12。  
> 本文只回答「做成什么样」与「按什么顺序做」，不写代码细节。

---

## 1. 目标与边界

### 1.1 一句话

一个 pywebview 的音乐库管理器：导入音频、维护歌曲/作者/标签、配置歌单与自适应规则，并把结果交给 player 与 simple 消费。

### 1.2 做什么

| 能力  | 说明                                                |
| --- | ------------------------------------------------- |
| 概览  | 启动首页：数据卡片、最近导入/编辑、待处理事项、常用入口（含启动 player 与 simple） |
| 导入  | 单文件导入、批量导入向导、可选 FFmpeg 清洗、MD5 去重                  |
| 歌曲  | 名称、作者（有序）、标签、文件信息、别名（二级入口）                        |
| 换源  | 用一个新文件替换某首歌的源文件，并把所有引用迁移到新 MD5                    |
| 歌单  | 手动歌单（有序）、条件歌单（集合）、系统内置默认歌单                        |
| 自适应 | 按歌单开关，记录最近 N 次操作，按跳过比例计算跳过概率                      |
| 标签  | 标签组 + 标签，支持必选/唯一约束                                |
| 作者  | 名称、简介、排序                                          |
| 维护  | 完整性检查、孤儿文件清理、统计重置                                 |
| 设置  | 通用 / 导入 / simple / player / 维护 五个分页               |
| 试听  | 窗口底部一条试听栏，复用同一套媒体服务                               |

### 1.3 不做什么

- 不做播放器的完整功能（播放、队列归 player）。
- 不做硬件媒体键、不做全局热键：三个程序都只响应窗口内按键。
- 不做封面、歌词、在线元数据刮削。
- 不做多用户、同步、云备份。
- 不做旧数据迁移：从空库开始。
- 不做音频转码：清洗只重封装，不改变编码参数。

### 2.2 入口

`manager.pyw` 只做三件事：把项目根放进 `sys.path`、延迟导入 `app.ui.manager.app`、调用 `main()`。不超过 30 行，不读配置、不建窗口。

`manager.bat` 按 `reference.md` 1.7 的模板：`@echo off` / `chcp 65001` / `setlocal` / `cd /d "%~dp0"` / 检查 `.venv\Scripts\pythonw.exe` / `start "" pythonw manager.pyw`。

### 2.3 依赖

| 依赖           | 用途          | 备注                    |
| ------------ | ----------- | --------------------- |
| `pywebview`  | 窗口与 JS 桥    | 依赖系统 WebView2 Runtime |

## 3. 数据模型

三份数据 + 一份设置。全部 UTF-8、四空格缩进、原子替换写入。

### 3.1 `config/library.json`

```json
{
  "version": 1,
  "authors": [
    { "uid": "6f1c…", "name": "Ludovico Einaudi", "description": "" }
  ],
  "tag_groups": [
    {
      "uid": "9a2b…",
      "name": "风格",
      "compulsory": false,
      "unique": true,
      "tags": [
        { "uid": "11aa…", "name": "古典" },
        { "uid": "22bb…", "name": "电影原声" }
      ]
    }
  ],
  "musics": [
    {
      "md5": "a1b2c3…",
      "names": ["Experience", "经验"],
      "authors": ["6f1c…"],
      "tags": ["11aa…"],
      "ext": "mp3",
      "duration_ms": 344000,
      "size": 8123456,
      "created_at": 1763000000,
      "updated_at": 1763000000
    }
  ]
}
```

| 字段            | 类型      | 说明                       |
| ------------- | ------- | ------------------------ |
| `md5`         | str(32) | 主键，清洗后文件内容的 MD5，全库唯一     |
| `names`       | str[]   | 有序；`[0]` 是主名称，其余是别名      |
| `authors`     | str[]   | 有序；`[0]` 是主作者，界面可拖拽排序    |
| `tags`        | str[]   | 无序集合                     |
| `ext`         | str     | `mp3` / `m4a`，决定磁盘文件名后缀  |
| `duration_ms` | int     | 0 表示未知（ffprobe 不可用时）     |
| `size`        | int     | 字节                       |
| `created_at`  | int     | 导入时间，秒                   |
| `updated_at`  | int     | 最近一次字段变更时间，秒；供概览「最近编辑」使用 |

**路径不存进数据。** 文件位置恒为 `assets/music/{md5}.{ext}`，由 `paths.py` 推导。这样移动程序目录、改盘符都不会让记录失效。

### 3.2 `config/playlists.json`

```json
{
  "version": 1,
  "default_uid": "d0d0…",
  "items": [
    {
      "uid": "d0d0…",
      "name": null,
      "builtin": true,
      "kind": "filter",
      "entries": [],
      "filters": [
        { "mode": "include", "target": "all", "values": [] }
      ],
      "created_at": 1763000000,
      "updated_at": 1763000000,
      "adaptation": {
        "enabled": false,
        "window": null,
        "min_plays": null,
        "base": null,
        "skip_seconds": null
      }
    },
    {
      "uid": "77aa…",
      "name": "深夜",
      "builtin": false,
      "kind": "manual",
      "entries": ["a1b2c3…", "d4e5f6…"],
      "filters": [],
      "created_at": 1763000000,
      "updated_at": 1763000000,
      "adaptation": {
        "enabled": false,
        "window": 100,
        "min_plays": 10,
        "base": 0.95,
        "skip_seconds": null
      }
    }
  ]
}
```

| 字段                          | 说明                                                  |
| --------------------------- | --------------------------------------------------- |
| `builtin`                   | 只有默认歌单为 `true`。不可删除、不可改名                            |
| `name`                      | `builtin` 时为 `null`，显示名走文案键 `playlist.default.name` |
| `kind`                      | `manual` 有序；`filter` 无序集合                           |
| `entries`                   | `manual` 的歌曲 MD5，有序                                 |
| `filters[].mode`            | `include` / `exclude`                               |
| `filters[].target`          | `all` / `music` / `playlist` / `tag` / `author`     |
| `filters[].values`          | 目标为 `all` 时为空数组                                     |
| `adaptation`                | 四项参数为 `null` 表示继承全局默认值                              |
| `created_at` / `updated_at` | 秒；`updated_at` 供概览「最近编辑」使用，任何字段变更都刷新                |

**默认歌单的初始状态**是「包含 · 全部歌曲」，所以开箱即用，simple 一启动就有歌可播。

### 3.3 `config/stats/<playlist_uid>.json`

```json
{
  "version": 1,
  "playlist": "d0d0…",
  "songs": {
    "a1b2c3…": {
      "records": "0110100101",
      "auto_skipped": 3,
      "last_played_at": 1763000000
    }
  }
}
```

- `records` 是环形缓冲区，`1` = 在阈值内被跳过，`0` = 未跳过；**从左到右由旧到新**。
- 新记录追加在末尾；长度超过 `window` 时从头部截断。
- `auto_skipped` 只用于统计展示，不参与判定。
- 每个歌单一个文件：写入量小、互不阻塞、损坏时只影响一个歌单。

### 3.4 `config/settings.json`

```json
{
  "version": 1,
  "common": {
    "theme": "system",
    "language": "zh-CN",
    "adaptation": {
      "window": 100,
      "min_plays": 10,
      "base": 0.95,
      "skip_seconds": 30
    }
  },
  "import": { "dir": "", "clean_audio": true },
  "simple": { "order": "shuffle" },
  "player": {
    "volume": 0.8,
    "order": "shuffle",
    "remember_progress": true,
    "last_playlist": null,
    "last_md5": null,
    "last_position_ms": 0
  }
}
```

顺序模式的取值：`simple.order` 只有 `shuffle` / `list_loop`；`player.order` 有 `shuffle` / `list_loop` / `repeat_one`。三个程序都不存在「顺序播放」这种模式。

`common`、`import`、`simple`、`player` 四节由 manager 的设置页写入，player 只回写 `last_*` 三个字段，simple 只读。

### 3.5 三个必须分开存的原因

1. **库与歌单分开**：歌单是「引用」，库是「实体」。换源时只动库里的 `md5` 和歌单里的引用，两边职责清楚。
2. **统计单独成文件**：player 与 simple 都会高频写统计，写 `library.json` 会把整个库置于并发风险中。
3. **设置单独一份**：三端都读，谁都不该为了读一个音量值去解析整个音乐库。

### 3.6 配置归属规则

**一个配置项只要被三个程序中两个或以上读取，就必须放进 `common`，界面上出现在「通用」页。** 只有单一程序使用的，才允许放在自己的节里。

| 配置                                              | 读取方                            | 归属                |
| ----------------------------------------------- | ------------------------------ | ----------------- |
| `theme`                                         | manager、player                 | `common` → 通用页    |
| `language`                                      | manager、player                 | `common` → 通用页    |
| `adaptation.window` / `min_plays` / `base`      | manager 配置、player 判定、simple 判定 | `common` → 通用页    |
| `adaptation.skip_seconds`                       | player 判定、simple 判定            | `common` → 通用页    |
| `import.dir` / `import.clean_audio`             | manager                        | 导入页               |
| `simple.order`                                  | simple                         | simple 页          |
| `player.volume` / `order` / `remember_progress` | player                         | player 页          |
| `player.last_*`                                 | player 自写自读                    | player 页（不展示，仅内部） |

这条规则是为了防止「同一个阈值在两个页面上各有一个输入框，改了一个另一个不生效」。以后新增配置项，先问一句「谁读它」，再决定放哪。

## 4. 核心规则

### 4.1 导入

```
选择文件 → 校验后缀 → [清洗] → 计算 MD5 → 落盘 assets/music → 写库 → 打开详情
```

1. 后缀白名单：`.mp3` / `.m4a`。其它格式直接拒绝并说明原因。
2. 清洗开启时：复制到 `assets/temp/` → `ffmpeg` 重封装（`-map 0:a -c copy -map_metadata -1 -fflags +bitexact`）→ 对产物算 MD5 → 移入 `assets/music/`。清洗失败要清理临时文件，不留垃圾。
3. 清洗关闭时：直接对原文件算 MD5，复制入库（复制而非移动，原文件不动）。
4. MD5 已存在：视为重复，不新建记录，提示「这首歌已在库中」并定位到已有条目。
5. 时长：`ffprobe -show_entries format=duration` 读取；取不到写 0，界面显示 `—`。
6. 名称默认取文件名主干；批量导入时按 `歌名 - 作者1, 作者2` 解析。
7. 导入即写盘（全自动保存），不需要再点保存。

**批量导入向导**（三步，同一个弹窗内切换）：

| 步骤   | 内容                                 |
| ---- | ---------------------------------- |
| 1 选择 | 文件列表，逐行可改「名称」「作者」，作者用逗号分隔，可标记「待补充」 |
| 2 标签 | 为这一批统一勾选标签；可跳过                     |
| 3 确认 | 汇总表 + 导入按钮；导入中显示进度，结束后给出成功/失败清单    |

失败不中断整批：逐条记录原因，最后一次性列出。

### 4.2 换源

用新文件替换某首歌的音频，同时保住它的名称、作者、标签、歌单归属与统计。

```
选新文件 → 算新 MD5 → 冲突检查 → 落盘新文件 → 迁移引用 → 删旧文件 → 出报告
```

1. 新 MD5 与原 MD5 相同：提示「内容一致，无需更换」，结束。
2. 新 MD5 已属于另一首歌：**中止**，提示冲突歌曲名称，让用户先处理（合并留到后续版本）。
3. 迁移按固定顺序执行，任何一步失败都要能回退到「旧状态仍可用」：
   - 新文件写入 `assets/music/{新md5}.{ext}`
   - `library.json` 中该条记录的 `md5` / `ext` / `size` / `duration_ms` 更新
   - 所有 `manual` 歌单的 `entries`：旧 → 新（保持位置）
   - 所有 `filter` 歌单的 `values`：旧 → 新
   - 所有统计文件中 `songs[旧]` → `songs[新]`（若新键已存在则按时间先后合并，超出窗口截断）
   - 旧文件送入回收站，重命名为「歌曲名（旧源）」+ 后缀
4. 完成后弹一份迁移报告：改了几个歌单、几条统计、旧文件去了哪里。

### 4.3 删除

| 对象  | 行为                                   |
| --- | ------------------------------------ |
| 歌曲  | 从库、歌单引用、统计中移除；音频文件重命名为「歌曲名.后缀」后送入回收站 |
| 作者  | 先阻止并列出引用歌曲；确认后连同引用一起移除（`force`）        |
| 标签组 | 同上，先阻止并列出用到的歌；确认后连同这些歌上的标签一起移除（`force`） |
| 标签  | 从所有歌曲的 `tags` 中移除后删除（属于组内编辑，不单独确认）   |
| 歌单  | 内置歌单不可删；被其它条件歌单引用时提示引用方，确认后可删        |

删除歌曲必须二次确认，确认文案里写明「音频文件会进入回收站，可从回收站还原」。

**回收站实现只在 Windows 生效**（`SHFileOperationW` + `FOF_ALLOWUNDO`）。非 Windows 平台直接删除文件并记日志——这个程序只服务 Windows，不做跨平台分支。

### 4.4 歌单解析

```
manual  → 按 entries 顺序，去重保序
filter  → 空集合起步，逐条条件求值：
          include → 并集
          exclude → 差集
          目标 all / music / playlist（递归，带环检测） / tag / author
```

- 解析结果对外是**去重集合**；只有 `manual` 保留顺序。
- 条件歌单引用另一个条件歌单时递归解析，用访问栈检测循环，发现环就抛 `PlaylistCycleError`，界面在该条件行标红，不影响其它条件。
- 解析是纯函数：输入歌单与库，输出集合，不写任何文件。
- 条件的值可以为空，空条件命中零首歌。界面允许先把对象类型选好再去挑值，删歌也可能把某个条件的值清空；如果把空值当校验错误，整条歌单会在下次加载时被当成坏记录丢掉。

### 4.5 自适应

#### 参数

| 参数             | 默认   | 范围       | 作用域     |
| -------------- | ---- | -------- | ------- |
| `enabled`      | 全部关闭 | —        | 歌单      |
| `window`       | 100  | 10–1000  | 歌单可覆盖全局 |
| `min_plays`    | 10   | 0–window | 同上      |
| `base`         | 0.95 | 0–0.99   | 同上      |
| `skip_seconds` | 30   | 5–300    | 同上      |

内置默认歌单不享受任何特殊待遇：自适应默认关，要用户自己在歌单详情里打开。这样「一装上就开始替你跳过」不会发生。

**作用域是歌单，不是歌曲。** 每个歌单（含默认歌单）各有一份 `enabled` 与四项参数，同一首歌在 A 歌单和 B 歌单里的记录、参数、概率互不相干。界面上：

- 歌单详情 → 编辑该歌单的配置，抽屉里看该歌单的逐曲统计。
- 歌曲详情没有「哪个歌单」的上下文，约定只显示**默认歌单**的数据，并注明来源。

#### 判定

对「歌单 P 中的歌 M」：

```
n = len(records)              # 已有记录条数
s = records.count("1")        # 其中跳过的条数

n <= min_plays        → p = 0
否则                   → p = min(base, 0.99) × (s / n)

random() < p → 自动跳过
```

例：`window=100`、`min_plays=10`、`base=0.95`，某歌已有 100 条记录、其中 50 条跳过 → `p = 0.95 × 0.5 = 0.475`。

#### 记录

| 情形              | 记录                        |
| --------------- | ------------------------- |
| 用户在阈值内主动切歌      | `1`                       |
| 用户播过阈值后切歌       | `0`                       |
| 自然播完            | `0`                       |
| 歌曲短于阈值、自然播完     | `0`                       |
| 自动跳过            | 不记录，只 `auto_skipped += 1` |
| 退出程序 / 切歌单 / 崩溃 | 不记录                       |

计时口径：**累计真实播放时长**。暂停不计时；拖动进度条跳过的时间不计入；只有实际播出声的秒数才算。这样「暂停去倒水再回来跳过」不会被误判成听了 30 秒。

#### 写入

一次播放结束只写一次：读该歌单的统计文件 → 追加记录 → 截断 → 原子替换。跨进程（player 与 simple 可能同时开着）用文件锁保护读改写，锁粒度是「一个歌单一个锁」。

### 4.6 完整性检查

分「快速」与「深检」两档，输出分组报告：

| 类别   | 检查内容                         | 可否自动修复     |
| ---- | ---------------------------- | ---------- |
| 文件缺失 | 记录存在但 `assets/music` 里没有对应文件 | 否，需重新导入或换源 |
| 孤儿文件 | 文件存在但库里没有记录                  | 可（送入回收站）   |
| 内容不符 | 深检：重算 MD5 与记录不符              | 否          |
| 引用断裂 | 歌单/歌曲引用了不存在的作者、标签、歌曲         | 可（移除失效引用）  |
| 标签约束 | 必选组为空、唯一组多选                  | 否，跳到该歌     |
| 统计残留 | 统计文件里有库里不存在的歌                | 可（清理）      |


深检要重算全部文件的 MD5，按文件大小显示进度，允许中途取消。

修复按类别执行，每类都能单独触发：孤儿文件送回收站、失效引用直接从歌曲与歌单上摘掉、统计残留按当前库清理。修复前不弹二次确认——这几类都是「删掉已经没有对应实体的数据」，没有别的解释；孤儿文件进的是回收站，可以还原。深检走任务通道（`start_integrity` + `poll_task`），按字节报进度，`cancel_task` 可中止。

## 5. 界面

### 5.1 骨架

```
┌──────┬────────────────────┬──────────────────────────────┐
│ 导航  │ 列表                │ 详情                          │
│ 76px │ 320px              │ minmax(0, 1fr)                │
│      │                    │                               │
│ 概览  │ 标题 + 计数 + 新建   │ 编辑区（卡片）                  │
│ 歌曲  │ 搜索框              │                               │
│ 歌单  │ ─────────────      │                               │
│ 标签  │ 行…                │                               │
│ 作者  │                    │                               │
│      │                    │                               │
│ ──── │                    │                               │
│ 设置  │ 多选操作条           │                               │
├──────┴────────────────────┴──────────────────────────────┤
│ 试听条（仅试听时出现，56px）                                  │
└─────────────────────────────────────────────────────────┘
```

- 三栏用 `grid-template-columns: 76px 320px minmax(0, 1fr)`；`minmax(0, 1fr)` 不能省，否则长路径会把详情区撑出横向滚动条。
- **概览是唯一没有列表栏的分区**：选中它时栅格切成 `76px minmax(0, 1fr)`，主区横跨两列。切走时再切回三栏，不要留下 320px 的空槽。
- 导航是图标 + 文字，选中态用 `--blue-soft` 底 + `--blue-text` 字。
- 列表与详情都要 `min-height: 0` + `overflow-y: auto`，滚动互不影响。
- 窗口默认屏幕 85%，最小 1100×680（低于这个宽度三栏会挤）。
- 启动默认停在概览。

### 5.2 概览

启动首页，回答三个问题：库里有什么、最近动了什么、有什么需要处理。

```
┌──────────────────────────────────────────────────────────┐
│  音乐库                                 [导入音乐] [批量导入] │
│  33 首歌 · 2 个歌单 · 12 位作者                             │
├──────────────────────────────────────────────────────────┤
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐        │
│  │  33 │ │2:48 │ │1.2G │ │  2  │ │ 12  │ │  3  │        │
│  │歌曲  │ │总时长│ │占用  │ │歌单  │ │作者  │ │标签组│        │
│  └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘        │
├──────────────────────────────┬───────────────────────────┤
│ [最近导入] [最近编辑]          │ 待处理                     │
│  Experience          2 小时前 │ ⚠ 3 首歌缺少必选标签   处理  │
│  Aware               昨天     │ ⚠ 1 个文件缺失         处理  │
│  Eternity            3 天前   │ ✓ 未发现其它问题            │
│  …                   全部 →  │                           │
├──────────────────────────────┴───────────────────────────┤
│ [打开播放器] [打开 simple] [新建歌单] [完整性检查] [设置]    │
└──────────────────────────────────────────────────────────┘
```

| 区域   | 内容                            | 交互                                                        |
| ---- | ----------------------------- | --------------------------------------------------------- |
| 头部   | 一句话摘要（歌曲数 · 歌单数 · 作者数）        | 右侧两个主操作：导入音乐、批量导入                                         |
| 数据卡片 | 歌曲数、总时长、库占用、歌单数、作者数、标签组数      | 六张都可点：歌曲 / 总时长 / 占用 → 歌曲分区；歌单 → 歌单分区；作者 → 作者分区；标签组 → 标签分区 |
| 最近   | 一个卡片两个页签：「最近导入」5 条、「最近编辑」5 条  | 点条目跳到对应详情；「全部 →」进该分区并按时间排序                                |
| 待处理  | 缺必选标签、文件缺失、孤儿文件、失效引用，最多 4 条   | 每条右侧「处理」跳到对应位置或打开检查报告；全清时显示 ✓ 空状态                         |
| 快速开始 | 打开播放器、打开 simple、新建歌单、完整性检查、设置 | 前两个是启动外部程序，后三个是站内跳转                                       |

设计取舍：

- 数字卡片不做图表、不做趋势。库里就几十上百首歌，画曲线是自欺欺人。
- 「最近编辑」靠每条记录上的 `updated_at`，歌曲与歌单各有一个，任何字段变更都刷新。这个字段只在内存里比对，不参与排序以外的逻辑。
- 待处理只统计**能行动**的问题。文件缺失点进去就是那首歌的详情，不是一份只读报告。
- 打开 simple 会弹出一个控制台窗口，这是它本来的形态；按钮文案写「打开 simple」，不写「启动」。

### 5.3 歌曲

**列表行**：主名称（14px）／副行「作者 · 时长 · 标签数」（12px，`--muted`）。缺必选标签的行右侧给一个琥珀色小点，hover 出说明。

**排序**：名称 / 导入时间 / 时长 / 作者。默认按名称。排序只影响显示，不改数据。

**多选**：Ctrl 点选、Shift 连选、行首复选框（hover 或已有选中时显示）。选中后列表底部浮出操作条：

```
已选 12 首    [加标签] [加入歌单] [删除]        取消
```

**详情卡片**：

| 卡片   | 内容                                       |
| ---- | ---------------------------------------- |
| 头部   | 主名称（21px）、作者 · 时长 · 大小 · 导入日期；右上「试听」「更多」 |
| 基本信息 | 名称输入、作者列表（拖拽排序、可搜索添加）、标签分组               |
| 文件   | MD5（可复制）、路径、大小、时长、「更换源文件」                |
| 自适应  | 默认歌单里的记录数、跳过率、自动跳过、下次概率（自适应按歌单独立配置） |

**别名**收在「更多 → 管理别名」里：一个窄弹窗，列表 + 增删 + 拖拽排序。主界面只显示主名称，搜索能命中别名。这样界面上不出现「别名」这个概念，但需要时找得到。

**标签编辑**：按标签组分区，每组一行胶囊。`unique` 组表现为单选（点第二个自动取消第一个），`compulsory` 组为空时给琥珀提示但不阻止保存——拦截式校验会让人卡在「必须先填标签才能改名字」的死循环里。约束违反由完整性检查兜底，并在列表行上标点。

### 5.4 歌单

**列表行**：名称 + 类型胶囊（手动/条件/默认）+ 歌曲数。

**类型在创建时确定，之后不可切换**：手动与条件的存储结构完全不同，切换等于清空内容。要换类型就新建一个，把歌曲重新加一遍——比一个「确定要清空吗」的弹窗更不容易出事。

**详情卡片**：

| 卡片  | 内容                                               |
| --- | ------------------------------------------------ |
| 头部  | 名称（内置歌单只读）、类型、命中数；右上「试听」「更多」                     |
| 内容  | `manual`：可拖拽的有序列表 + 搜索添加；`filter`：条件行编辑器 + 实时命中数 |
| 自适应 | 总开关；四个参数，每项带「继承全局」开关；「查看统计」                      |

**条件行**：`[包含/排除] [全部/歌曲/歌单/标签/作者] [对象选择器] [删除]`。改动即时重算命中数，不点按钮。循环引用在该行下方红字提示。

**统计面板**是右侧抽屉（不是弹窗）：占宽度 420px，从右侧滑出，主界面仍可见。内容是一张表：歌曲 / 记录数 / 跳过率 / 自动跳过 / 下次概率，跳过率列用横向条形。顶部有「清空本歌单统计」和每行的「清空」。

抽屉而不是弹窗，是因为它属于「看一眼就关」的辅助信息，弹窗会遮住正在调的参数。

### 5.5 标签

列表：标签组名称 + 「必选/唯一」小标 + 标签数。详情：名称、两个开关、标签列表（增删改名，按名称排序显示）、引用统计（多少首歌用了这组标签）。

### 5.6 作者

列表：作者名 + 歌曲数。详情：名称、简介、歌曲列表（只读，点击跳转）。

作者列表**有序**，支持拖拽排序；这个顺序会体现在歌曲详情的作者选择器和 player 的显示上。

### 5.7 设置

导航底部的「设置」进入一个独立分区，左侧是二级导航。分页的划分遵守 §3.6 的归属规则：

| 分页     | 内容                                                                                           | 谁读                        |
| ------ | -------------------------------------------------------------------------------------------- | ------------------------- |
| 通用           | 主题（跟随系统/浅色/深色）、语言（当前仅中文，占位）、自适应默认值（window / min_plays / base）、跳过判定阈值（skip_seconds）、试听默认音量、数据目录、日志目录 | manager + player + simple |
| 轻量音乐播放器      | 播放模式（随机 / 列表循环）、默认歌单（只读显示 + 跳转到该歌单）                                                          | 仅 simple                  |
| 音乐播放器        | 默认音量、播放模式（随机 / 列表循环 / 单曲循环）、记住进度                                                             | 仅 player                  |
| 导入           | 默认导入目录、是否清洗音频、FFmpeg 状态检测                                                                    | 仅 manager                 |
| 维护           | 调试状态（关掉 player 与 simple 的全部自适应记录）、完整性检查（快速/深检）、孤儿文件清理、清空全部统计、打开数据目录 / 日志目录                          | manager + player + simple |

- 「前 30 秒」这个阈值放在**通用**，因为它同时被 player 和 simple 读取。不要在两处各放一个输入框。
- 自适应四项（window / min_plays / base / skip_seconds）全在通用页；单个歌单可以在歌单详情里覆盖，覆盖入口只在歌单详情，不在设置页。
- simple 与 player 的分页在这里占好位置，各自程序只读这些值。这样「调另一个程序的配置」不用去改 JSON。
- 每个分页改完即生效，没有「保存」按钮；涉及路径的字段在失焦时校验。

### 5.8 组件与状态

- 只用 `reference.md` 3.5 的令牌与十档字号，不新增颜色。
- 按钮层级：主操作 `primary`（一屏一个）、常规白底、次要 `ghost`、破坏性入口 `danger-ghost`、确认弹窗里 `danger`。
- 弹窗统一三段式：头 / 可滚动主体 / 右对齐按钮；`max-height: 82vh`。
- Toast 只报操作结果，字段错误标在字段上。
- 列表重建前记 `data-focus-id`，重建后恢复焦点；列表用 roving tabindex。
- 空状态：96px 线性图标 + 一句标题 + 一句说明 + 一个主按钮（如「导入第一首歌」）。

## 6. 前后端契约

### 6.1 快照

每个改变状态的方法都返回完整快照，前端整体重绘：

```json
{
  "ok": true,
  "message": "",
  "section": "overview",
  "selection": { "kind": "music", "uid": "a1b2…" },
  "library": { "musics": [], "authors": [], "tag_groups": [] },
  "playlists": [],
  "settings": {},
  "counts": {
    "musics": 33,
    "playlists": 2,
    "authors": 12,
    "tag_groups": 3,
    "total_duration_ms": 10081000,
    "total_size": 1288490188
  },
  "overview": {
    "recent_imported": [{ "md5": "a1b2…", "title": "Experience", "at": 1763000000 }],
    "recent_edited": [{ "kind": "playlist", "uid": "77aa…", "title": "深夜", "at": 1763000000 }],
    "issues": [{ "kind": "missing_tag", "count": 3 }, { "kind": "missing_file", "count": 1 }]
  },
  "errors": []
}
```

`counts` 与 `overview` 由后端算好，前端不遍历全库做统计——列表渲染已经够忙了。

前端只保留视图状态：搜索词、滚动位置、多选集合、抽屉开合、概览页签。业务数据一律来自快照。

### 6.2 方法

| 类别  | 方法                                                                                                                           | 返回                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 读取  | `get_state` / `get_strings` / `get_playlist_stats` / `get_music_stats`                                                       | 数据                                                 |
| 导航  | `select_section` / `select_item`                                                                                             | 快照                                                 |
| 概览  | `get_overview` / `launch_player` / `launch_simple`                                                                           | 数据 / `{ok}`                                        |
| 歌曲  | `import_files` / `update_music` / `set_music_authors` / `toggle_tag` / `replace_source` / `delete_musics`                    | 快照或任务                                              |
| 批量  | `batch_add_tags` / `batch_add_to_playlist`                                                                                   | 快照                                                 |
| 别名  | `add_alias` / `remove_alias` / `move_alias`                                                                                  | 快照                                                 |
| 歌单  | `create_playlist` / `update_playlist` / `set_entries` / `add_filter` / `update_filter` / `remove_filter` / `delete_playlist` | 快照                                                 |
| 自适应 | `update_adaptation` / `reset_stats`                                                                                          | 快照                                                 |
| 标签  | `create_tag_group` / `update_tag_group` / `add_tag` / `rename_tag` / `remove_tag` / `delete_tag_group`                       | 快照                                                 |
| 作者  | `create_author` / `update_author` / `move_author` / `reorder_authors` / `delete_author`                                      | 快照                                                 |
| 设置  | `update_settings` / `set_theme` / `clear_all_stats` / `refresh_status` / `browse_folder`                                     | 快照 / `{path}`                                       |
| 系统  | `browse_audio` / `open_data_dir` / `open_log_dir` / `run_integrity` / `start_integrity` / `fix_issues`                       | 值或快照                                               |
| 试听  | `audition_url`（返回带令牌的本地地址，播放/暂停/进度都在网页里用 `<audio>` 控制）                                            | `{ok, url, title, duration_ms}`                       |
| 任务  | `start_import` / `start_replace_source` / `poll_task` / `cancel_task`                                                        | `{ task_id }` / `{ done, total, current, errors, result }` |

规则：

- 越界或非法参数不抛异常，原样返回当前快照。网页收到 Python traceback 是最难排查的一类故障。
- 逐字符触发的输入（名称、简介）走 `{"ok": bool}` 的轻量返回，前端做 120ms 防抖；结构性操作前先 `flushPending()`。
- 耗时操作（导入、深检）必须走任务：`js_api` 里不阻塞。
- `launch_player` / `launch_simple` 用 `subprocess.Popen` 拉起同目录的入口，工作目录固定为项目根；player 用 `pythonw.exe` 无控制台，simple 用 `python.exe` 并 `CREATE_NEW_CONSOLE`。simple 带单实例守卫：已在运行时直接返回 `{ok: false, message: "simple 已经在运行"}`，不重复拉起。启动失败返回 `{ok: false, message}`，不抛异常。

### 6.3 任务

```
start_import(paths) → { task_id }
poll_task(task_id)  → { state: "running|done|failed", done, total, current, errors }
```

前端每 200ms 轮询一次，进度条走 `done/total`。任务完成后再拉一次 `get_state`。

## 7. 线程与并发

| 线程             | 做什么                 | 禁止                |
| -------------- | ------------------- | ----------------- |
| UI 线程（webview） | 窗口、事件、关闭握手          | 阻塞                |
| `js_api` 线程    | 读写 JSON、解析歌单（都是毫秒级） | 跑 ffmpeg、跑深检      |
| 任务线程           | 导入、深检、批量删除          | 直接调 `evaluate_js` |
| 媒体服务线程         | 提供 Range 请求         | 碰业务数据             |

- 库写入用「读-改-写 + 原子替换」，全局一把锁；统计写入用「一歌单一锁」。
- 跨线程只传数据。任务线程只更新任务表，前端自己轮询。
- 管理器单实例：命名互斥量检测，已在运行就弹一句「管理器已经在运行」并退出，避免两个进程互相覆盖 `library.json`。player 与 simple 不限制。
- 拉起 player / simple 用 `subprocess.Popen`，不等待、不捕获输出；父进程退出后子进程继续运行。simple 需要 `CREATE_NEW_CONSOLE`，否则它的输出会落到管理器的空控制台上。

## 8. 错误处理

| 场景                                     | 策略                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------- |
| `library.json` / `playlists.json` 结构损坏 | `ConfigError` → 记日志 → 弹窗给日志路径 → 退出，不静默重建                                   |
| `settings.json` 缺字段或越界                 | 读时夹取，回退默认值，记 warning，继续运行                                                  |
| 单个歌曲记录字段非法                             | 跳过该条，记 warning，界面提示「N 条记录已跳过」，其余照常                                         |
| 导入单个文件失败                               | 记入批次错误清单，继续处理下一个                                                           |
| FFmpeg 缺失                              | 导入前检测，弹窗给出安装指引与「本次不清洗」的选项                                                  |
| 写盘失败                                   | Toast + 日志，界面保持原值，不假装成功                                                    |
| 未捕获异常                                  | `sys.excepthook` 记录 + 原生 `MessageBoxW`，`logger.complete()` 后 `os._exit(1)` |

## 12. 偏离标准

| 条目         | 偏离                               | 原因                                       |
| ---------- | -------------------------------- | ---------------------------------------- |
| 2.10 本地化   | 只出 `zh-CN.json`，暂不出 `en-US.json` | 个人工具，先保证文案层结构正确；补英文只需加一个文件               |
| 1.6 目录     | 用 `config/` 存运行期数据，未再分 `data/`   | 与 reference 一致；统计放 `config/stats/` 只是子目录 |
| 3.1 选型     | 管理界面用 pywebview，simple 用命令行      | simple 是打开即播的一次性工具，命令行启动最快               |
| 2.11 线程    | 管理器加单实例互斥量                       | 两个进程同时写 `library.json` 会丢数据              |
| 3.10 键盘    | 不做硬件媒体键与全局热键                     | 只服务单机听歌，窗口内按键已经够用，也避免抢别的程序的键             |
| 3.10.2 快捷键 | 不设 `Ctrl+S`                      | 全自动保存，每次改动已落盘，再要求用户「保存」是多余动作             |

## 13. 已确认的决定

| 事项           | 决定                                   |
| ------------ | ------------------------------------ |
| 导入格式         | 只收 `.mp3` / `.m4a`                   |
| 中文排序         | 不引入 `pypinyin`，按 Unicode 与导入时间排      |
| 换源撞已有 MD5    | 中止并提示冲突歌曲，不做合并                       |
| 试听条          | 窗口底部全局一条                             |
| 删除被引用的作者/标签组 | 阻止，并列出引用方                            |
| 管理器单实例       | 需要，命名互斥量                             |
| 批量加标签        | 追加，另给「先清空这些组」开关                      |
| 统计面板         | 右侧抽屉，不用弹窗                            |
| 内置默认歌单的自适应   | 默认关闭，用户自己开                           |
| 媒体键 / 全局热键   | 全部砍掉；三个程序都只响应窗口内按键                   |
| `setup.bat`  | 提供                                   |
| 主题           | 默认跟随系统                               |
| 概览           | 作为启动首页，取代「默认进歌曲页」                    |
| 配置归属         | 被两个以上程序读取的配置一律进 `common`（通用页），见 §3.6 |
